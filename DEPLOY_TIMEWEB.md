# Развёртывание ПожТендера в Timeweb Cloud

Проект запускается как backend-приложение из `Dockerfile`. Контейнер слушает порт `8080`, а проверку состояния Timeweb выполняет по адресу `/health`.

## Создание приложения

1. Поместить этот каталог в приватный Git-репозиторий. Секреты и файл `.env` не добавлять.
2. В Timeweb Cloud открыть **App Platform → Создать приложение → Backend → Dockerfile**.
3. Подключить репозиторий и ветку, содержащую сайт. Контекст сборки — корень репозитория, Dockerfile — `Dockerfile`.
4. Указать порт `8080` и healthcheck `/health`.
5. Сначала развернуть без боевых секретов. Timeweb выдаст технический домен с HTTPS.
6. В переменных приложения задать `PUBLIC_ORIGIN` равным выданному HTTPS-адресу без завершающего `/`.

## Переменные Robokassa

Добавлять только в панели Timeweb, не в Git:

- `ROBOKASSA_MERCHANT_LOGIN`
- `ROBOKASSA_PASSWORD_1`
- `ROBOKASSA_PASSWORD_2`
- `ROBOKASSA_TEST_MODE=true` для первой проверки
- `ROBOKASSA_B2B_RECEIPT_CONFIRMED=false`, пока Robokassa не подтвердит корректное формирование B2B-чека НПД

Пока последняя переменная равна `false`, кнопка оплаты безопасно ведёт на страницу «Онлайн-оплата подключается» и не создаёт платёж.

## Настройки магазина Robokassa

После получения постоянного домена указать в кабинете магазина:

- Result URL: `https://ДОМЕН/api/payment/result`
- Success URL: `https://ДОМЕН/payment/success`
- Fail URL: `https://ДОМЕН/payment/failed`
- метод Result URL: POST (сайт также принимает GET)
- алгоритм подписей: SHA-256

Сначала провести тестовый платёж. Включать боевой режим и менять `ROBOKASSA_B2B_RECEIPT_CONFIRMED` на `true` только после проверки, что чек для ООО/ИП содержит корректные реквизиты покупателя и услуги.
